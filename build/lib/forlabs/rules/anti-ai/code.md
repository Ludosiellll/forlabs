# Анти-ИИ: код

Код в листингах и файлах лабы — код студента 2 курса, который учится по методичке. Он должен выглядеть так, будто его написали руками на паре.

## Стиль методички
- Если в запросе есть примеры кода из методички, повторяй их стиль: имена, способ ввода и вывода, форматирование, порядок объявлений, конструкции.
- Используй только то, что уже было в курсе: в методичке этой и прошлых лаб, в памяти предмета. Если в методичке нет LINQ, лямбд, switch-выражений, record, кортежей, интерполяции строк, async/await, обобщённых классов, шаблонов проектирования — не пиши их.
- Решай задачу прямо и полностью. Один файл, если методичка даёт один файл. Без интерфейсов, фабрик, конфигов, логгеров и «расширяемой архитектуры», если задание их не просит.
- Имена простые и понятные: латиница для C#, Java, Go, PHP, JS (как в методичке), русские имена в 1С. Без «Manager», «Handler», «Helper», «Util», если методичка их не вводит.
- Данные в примерах — правдоподобные и на русском: товары, блюда, города, должности. Не «Test», «foo», «Item1», «John Doe», «Lorem ipsum».
- Объём по заданию: не добавляй меню, проверки и функции, которых задание не просит.

## Комментарии
- Мало: только там, где без них непонятно. Коротко, по-русски, со строчной буквы: «// ввод данных», «// пересчет суммы».
- Запрещены:
  - английские слова в комментариях;
  - TODO, FIXME, NOTE, Fallback, «заглушка»;
  - нумерованные комментарии-заголовки: «// 1. Модуль …», «// Шаг 2: …»;
  - doc-комментарии: /// <summary>, /** @param */, «// Параметры: …»;
  - пересказ строки кода словами, пояснения «для совместимости», «на всякий случай».
- В BSL в комментариях нет ни одного английского слова.
- Особые требования предмета (например, без комментариев в индивидуальном задании КПИЯП) важнее этого раздела.

## Вывод программы
- Все надписи по-русски, как написал бы студент: «Введите число n: », «Максимальный элемент массива: 58».
- Без английских меток и слов: «[Service]:», «Error:», «Done», «Press any key».
- Без декоративных разделителей и рамок: «=====», «-----», «*****», «###», «>>>», псевдографика. Заголовок блока вывода — обычная строка с двоеточием: «Список рецептов:».
- Без эмодзи и значков: ✓, ✅, ❌, ▶, →, •.
- Без бодрых отчётов об успехе: «Операция успешно выполнена!», «Документ успешно создан и проведен». Сообщение пиши, только если оно нужно по заданию, и коротко.

## Обработка ошибок
- try/catch (в 1С Попытка…Исключение) — только если его требует задание или без него программа падает на обычном вводе. Пустых обёрток и обёрток «на всякий случай» нет.
- Проверка ввода — способом из курса: в C# цикл while (!int.TryParse(Console.ReadLine(), out n)), в Go if с сообщением и return.
- Не проверяй то, что не может случиться.

## 1С (BSL)
- Диалоги синхронные, как в курсе: ВвестиЧисло, ВвестиСтроку, Предупреждение. Не используй ОписаниеОповещения, ПоказатьПредупреждение, ПоказатьВводЧисла и другие асинхронные варианты.
- Диалоги ввода не заменяй константами.
- Запросы — как из «Конструктора запросов»: ключевые слова КАПСОМ (ВЫБРАТЬ, ИЗ, ГДЕ, СГРУППИРОВАТЬ ПО, УПОРЯДОЧИТЬ ПО, КАК), каждая строка продолжения начинается с «|» и табуляции.
- Нет пустых #Область…#КонецОбласти, пустых процедур, пустых Попытка…Исключение вокруг реквизитов. Модуль без логики — пустой.
- Документ или элемент ищи по номеру или коду, как в методичке, без перебора Выбрать()/Следующий() на случай неудачи.

Пример запроса:
```
Запрос = Новый Запрос;
Запрос.Текст =
	"ВЫБРАТЬ
	|	ПродажиОбороты.Номенклатура КАК Номенклатура,
	|	ПродажиОбороты.СуммаОборот КАК Сумма
	|ИЗ
	|	РегистрНакопления.Продажи.Обороты КАК ПродажиОбороты";
```
