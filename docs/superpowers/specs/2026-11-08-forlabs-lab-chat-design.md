# ForLabs: чат «Правки» у каждой лабы — спецификация

Владелец одобрил дизайн (панель слева на экране лабы, все пункты ниже) и разрешил делать без вопросов.

## 1. Зачем

Преподаватель просит изменения, которых нет в методичке: «во втором задании ещё проверять, что число
положительное», «перепиши цикл на while», «вывод подробнее», «вариант не 14, а 7». Студент пишет это в чат лабы,
ИИ правит отчёт точечно, проверяет и пересобирает документ.

## 2. Поведение

1. Сообщение в чате → ИИ решает, что это:
   - **правка** — какие задания, ответы на контрольные вопросы, вариант или вывод затронуты;
   - **вопрос** («почему тут for?») — отвечает, отчёт не меняет;
   - **неясно** — переспрашивает, отчёт не меняет.
2. Правка точечная: модель получает текущие блоки задания с номерами и возвращает новое содержимое, где
   нетронутые блоки помечены «оставить как есть» (`keep`). Такие блоки переносятся без изменений, вместе со
   вставленными скриншотами. Рисунок, который после правки надо переснять (поменялся код или результат),
   помечается `retake` — его место снова попадает в «Нужно от тебя».
3. Изменения разбора: вариант (номер и текст из методички), вывод (свой текст). Текст варианта модель берёт
   только из текста методички, без выдумки.
4. После правки: проверка по стандарту и на признаки ИИ (с автоисправлением), вёрстка. Ответ в чате:
   что изменено по заданиям, какие рисунки переснять.
5. «Запомнить для следующих лаб» (галочка у сообщения): из сообщения получается короткое требование
   («Код с комментариями к каждому методу»), оно хранится **отдельно** от памяти-выжимки предмета
   (`<предмет>.teacher`, не обрезается вместе с выжимками) и подставляется во все промпты написания и
   правки этого предмета для профиля.
6. Версии: перед каждой правкой сохраняются разбор и отчёт (последние 10). У ответа с правкой — кнопка
   «Вернуть как было». Откат пересобирает документ и пишет в чат, к чему вернулись.
7. Сбой на середине — разбор и отчёт возвращаются к версии до правки, в чате — понятное сообщение.
8. История чата хранится в состоянии лабы (в облаке — вместе с лабой, видна с любого компьютера).
9. Чат доступен, когда отчёт уже написан. Пока по лабе идёт работа, отправка отклоняется (как другие действия).

## 3. Данные

- `ChatMessage(id, role: user|assistant, text, at, remember: bool, kind: edit|answer|question|failed|revert,
  changed: list[str], retake: list[str], version: int|None)`.
- `LabVersion(id, at, label, spec, report)`; `LabState.chat`, `LabState.versions` (≤ 10).

## 4. Модуль `forlabs/pipeline/chat.py`

- `plan_edit(...) -> EditPlan(kind, reply, tasks: [{n, instruction}], questions: [{n, instruction}],
  variant: int|None, variant_text: str|None, conclusion: str|None, remember: str|None)`.
- `revise_section(...) -> (TaskSection, retake: list[str])` — блоки `keep`/новые/`retake`.
- `revise_answers(...) -> list[QA]`.
- `Pipeline.chat(st, message, remember) -> LabState`, `Pipeline.revert(st, version_id) -> LabState`.

## 5. Интерфейс

Левая колонка экрана лабы: блок «Правки» вместо «Переделать» — лента сообщений (своя прокрутка),
поле «Что сказал преподаватель…», галочка «Запомнить для следующих лаб по предмету», кнопка «Отправить»
(Ctrl+Enter). У ответов с правкой — «Вернуть как было». «Переписать задание целиком» остаётся (свёрнуто).
Колонка шире (до 340 px). Пока ИИ работает — как при выполнении: полоса занятости, журнал шагов.

## 6. Проверка

FakeLLM-тесты: план (правка/вопрос/неясно), точечная правка с `keep` и сохранением скриншота, `retake`,
смена варианта и вывода, ответы на вопросы, запоминание, откат, восстановление при сбое, маршруты и отказ
при занятой лабе. Живой прогон на настоящей модели: правка лабы ССП ЛР4. Скриншоты панели.
