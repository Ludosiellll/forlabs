# ForLabs: админ-панель — спецификация

Дополняет `2026-11-08-forlabs-design.md` (§16 «Многопользовательский режим»). Место панели выбрал
владелец: **внутри ForLabs**, раздел «Админ» виден только администратору в облачном режиме. Дальше
владелец разрешил делать без вопросов: спецификация → план → реализация → проверка.

## 1. Задачи администратора

1. Видеть всех участников: имя, почта, ФИО и группа из их профилей, роль, когда пришёл, когда был активен.
2. Выдавать каждому **свой ключ модели**: вставить, заменить, убрать. Участник ключ не видит никогда.
3. Управлять **подпиской** (доступ до даты): +7 дней, +30 дней, до выбранной даты, бессрочно, забрать
   сейчас; одобрить новый аккаунт или отключить. Заметка к участнику («оплатил за ноябрь»).
4. Видеть **остаток на ключе** у провайдера и оценку «хватит примерно на N лаб».
5. Видеть, **что делают**: профили, лабы (предмет, номер, статус, даты), расход токенов по дням и
   по каждой лабе, скачать отчёт .docx участника (только чтение).
6. **Графики**: расход токенов по дням (по участникам), новые лабы по неделям, расход участника по дням.
7. **История** действий администратора по участнику.

Участник видит у себя: срок подписки, остаток на своём ключе; при окончании подписки — понятное
сообщение вместо ошибки модели.

## 2. Данные (миграция `0003_admin.sql`)

- `members`: новые столбцы `access_until timestamptz null` (null — бессрочно),
  `allow_shared_key boolean default true`, `last_seen_at timestamptz`.
  Действующий доступ к модели: `approved and (role = 'admin' or access_until is null or access_until > now())`.
  Подписка ограничивает только модель: свои лабы участник читает и скачивает и после окончания.
- `member_notes(user_id, note)` — заметка администратора; читает и пишет только администратор (миграция 0004:
  участник читает свою строку `members` целиком, поэтому заметке там не место).
- `labs`: столбец `created_at timestamptz default now()` (для графика «лабы по неделям»).
- `llm_usage`: столбцы `lab text` (ключ лабы `профиль/предмет/номер`) и `key_kind text`
  (`own` | `shared`).
- `private.member_keys(user_id pk, secret_id uuid, last4 text, set_at timestamptz)`; сам ключ —
  в `vault.secrets` (шифрование Supabase Vault). Схема `private` не видна через API.
- `public.member_events(id, user_id, actor, kind, detail jsonb, created_at)` — история; пишет
  только триггер и функции; читает только администратор.

### Функции

| Функция | Кто вызывает | Что делает |
|---|---|---|
| `admin_set_key(target, api_key)` | администратор (проверка внутри) | кладёт ключ в Vault, хранит last4, пишет событие; возвращает last4 |
| `admin_clear_key(target)` | администратор | удаляет ключ из Vault, событие |
| `admin_keys()` | администратор | `user_id, last4, set_at` по всем |
| `admin_usage_daily(days)` | администратор (RLS) | токены по дням и участникам |
| `admin_usage_by_lab(target)` | администратор (RLS) | токены и запросы по лабам участника |
| `llm_key_for(target)` | только `service_role` (прокси) | расшифрованный ключ участника или null |

Изменения доступа (approved, access_until, note, allow_shared_key, display_name) администратор
делает обычным обновлением строки `members` (политика уже есть); триггер пишет событие в
`member_events` только при изменении этих полей. Обновление `last_seen_at` событий не пишет.

### Права чтения

Администратор дополнительно **читает** (не меняет) `labs`, `student_profiles` и файлы в bucket
`labs` всех участников. Участник по-прежнему видит только своё.

## 3. Прокси модели (Edge Function `llm`)

Логика выносится в чистый модуль `logic.ts` (тестируется Node без сети):

1. Вход и одобрение — как раньше.
2. Подписка: не администратор и `access_until <= now` → 403 `subscription expired: <ISO-дата>`.
3. Ключ: свой из Vault; если нет — общий `LLM_API_KEY`, если `allow_shared_key` и он задан; иначе
   503 `no key assigned`.
4. Учёт: `llm_usage` с `lab` (заголовок `X-ForLabs-Lab`, URL-кодирован) и `key_kind`;
   `members.last_seen_at = now()`.
5. Новый маршрут `POST …/llm/balance`: участник получает остаток своего ключа; администратор —
   по списку `user_ids` и общий ключ. Остаток берётся у провайдера `GET {BASE}/balance`
   (`token_balance`); ошибка провайдера по одному ключу не ломает ответ (null + текст).

## 4. Приложение

- `LLM.with_headers()` — копия клиента с доп. заголовками; конвейер помечает все запросы лабы.
- Новые ошибки модели: «Подписка закончилась DD.MM.YYYY — напиши администратору»,
  «Администратор ещё не выдал тебе ключ».
- `CloudStore`: методы администратора (обзор, карточка, доступ, ключ, заметка, события, остатки,
  скачивание отчёта участника) и `my_balance()`.
- Страницы (только администратор, только облако; иначе — переход на главную):
  - `/admin` — показатели (участники, с доступом, токены за 30 дней, лабы за 30 дней), график
    расхода по дням (стопкой, до 5 участников + «остальные»), график новых лаб по неделям,
    таблица участников (статус подписки, ключ, остаток, расход 30 дней, лабы всего/сдано,
    последняя активность). Остатки подгружаются после открытия страницы (не тормозят её).
  - `/admin/u/{uid}` — карточка: доступ и кнопки подписки, заметка и имя, ключ (••••1234,
    заменить, убрать, разрешить общий), остаток и оценка, профили, график расхода по дням,
    таблица лаб с токенами и скачиванием .docx, история.
  - `/users` ведёт на `/admin`.
- У участника в шапке: «Подписка до 12.12.2026» / «без срока»; за 3 дня до конца — жёлтая плашка,
  после — красная. На странице настроек — остаток своего ключа.
- Графики — встроенный SVG, без внешних библиотек и сети (работает в окне приложения офлайн).

## 5. Ошибки и крайние случаи

- Администратор не может снять доступ или роль с себя (триггер уже есть) и не может «забрать»
  подписку у себя (кнопки скрыты, сервер не ограничивает администратора по дате).
- Ключ пустой или короче 8 символов — отказ с сообщением; пробелы по краям обрезаются.
- Провайдер недоступен при запросе остатка — в ячейке «нет связи», страница работает.
- Участник без профилей и лаб — пустые состояния с пояснением, без ошибок.
- Удалённый из Auth пользователь исчезает каскадно (ключ — вместе с записью Vault через триггер
  на удаление `member_keys`).

## 6. Проверка

- Python: FakeSupabase (REST, RPC, функции) — все страницы и методы, права (участник получает
  переход, а не данные), формат графиков.
- TypeScript: `node --experimental-strip-types --test` для `logic.ts`.
- База: `supabase/admin_check.sql` — транзакция с гарантированным откатом на живом проекте:
  ключ кладётся и читается только сервисной ролью, участник не может вызвать функции администратора
  и прочитать чужие лабы, администратор может, события пишутся.
- Живой прогон прокси без входа (401) и после развёртывания; скриншоты страниц, 5 проходов по виду.
