# Программы лаб: проект, сборка, запуск, настоящие скриншоты

Владелец одобрил в чате 2026-11-09: «делай, только максимально протестируй… языков много: плюсы, шарпы, пайтон, джава,
джаваскрипт, пхп, го, а также mysql». Совмещённый вариант: свои программы — сценарий и изолированный запуск, чужие
программы — режим «ИИ управляет окном»; студента просить только в крайнем случае.

## Что получает студент

1. Папка проекта рядом с отчётом: `<папка сдачи>/<Предмет>/ЛР N/Проект <Имя>/` — открывается в своей среде
   (Visual Studio, VS Code, IDEA), собирается и запускается. На странице лабы: «Открыть папку проекта», «Скачать .zip».
2. Листинги в отчёте — из этих файлов (код в отчёте = код, который компилируется).
3. Рисунки со снимками окон программы ForLabs делает сам: запускает собранную программу, вводит данные по
   сценарию, снимает окно. В «Нужно от тебя» остаётся только то, что сделать нельзя, — с причиной.
4. Для чужих программ (1С, Packet Tracer, Visual Studio, SSMS, MySQL Workbench) — кнопка «Пусть ForLabs сделает сам»
   у рисунка: модель видит снимок одного окна и кликает только внутри него (этап 3).

## Языки и инструменты (компьютер студента, Windows)

| Язык / вид | Найти | Собрать | Запустить | Снимок |
|---|---|---|---|---|
| C# консоль | `dotnet --list-sdks` | `dotnet build` по шаблону csproj ForLabs | exe в консоли | окно консоли |
| C# WinForms / WPF | то же | то же (`UseWindowsForms`/`UseWPF`) | exe | окно программы после шагов UI Automation |
| C++ | vswhere → cl (vcvars64), иначе g++/clang в PATH | компилятор, все .cpp | exe в консоли | окно консоли |
| Python | `py -3` / python в PATH (не Python самого ForLabs) | — | `python main.py` в консоли; tkinter — окно | консоль / окно |
| Java | JAVA_HOME / javac в PATH | `javac -encoding UTF-8 -d out` | `java -cp out Main`; Swing — окно | консоль / окно |
| JavaScript (Node) | node | — | `node main.js` в консоли | консоль |
| HTML/CSS/JS | Edge (есть всегда) | — | окно Edge с отдельным профилем, file:// | окно браузера |
| PHP | php в PATH, XAMPP | — | консоль `php main.php`; сайт — `php -S 127.0.0.1:порт` + Edge | консоль / браузер |
| Go | go | `go build` | exe в консоли | консоль |
| MySQL | mysql.exe (папка MySQL Server), служба запущена | — | `mysql` в окне консоли, ввод запросов по одному | окно консоли с `mysql>` |

Нет инструмента — проект всё равно пишется, рисунки остаются студенту с причиной («нет .NET SDK — …»).
Кириллица в консоли: перед запуском кодовая страница консоли 65001; C++ собирается с UTF-8 (`/utf-8`, у g++ по умолчанию).

## Конвейер (этап «Проект» между «Текст отчёта» и «Проверка»)

1. Нужен ли проект: предмет `kind == "code"` или в отчёте есть листинги на поддерживаемом языке.
2. Модель: `ProjectPlan` (JSON) — язык, вид, имя, файлы, какие листинги из каких файлов, сценарий каждого снимка.
3. Проверка плана: пути только внутри проекта, разрешённые расширения, лимиты размера; файлы сборки (csproj, pom,
   go.mod, CMake) пишет ForLabs по своим шаблонам, модель — только исходники.
4. Проверка кода на опасное (по языку): удаление/запись файлов вне папки программы, запуск процессов, реестр, сеть,
   P/Invoke, рефлексия с загрузкой сборок, `eval`/`exec`, `os.system`, `Runtime.exec`, `DROP DATABASE` чужих баз…
   Нашлось — проект пишется, но сам ForLabs его не запускает (рисунки — студенту, причина названа).
5. Сборка; ошибки компиляции → модель исправляет файлы, до 3 кругов.
6. Снимки: каждый запуск — отдельная папка `LocalLow\ForLabs\runs\…` (метка Low), процесс с уровнем целостности
   Low в задании (job): лимит памяти, процессов, времени; закрытие задания убивает всё. Шаги сценария:
   WinForms/WPF/Swing/tkinter — UI Automation (`set`, `select`, `click`, `check`, `wait`), консоль — ввод клавиш в окно
   (WriteConsoleInput), браузер — адрес и прокрутка. Снимок — PrintWindow окна (не весь экран), пустой снимок = ошибка.
   Перед снимком — проверка ожидаемого текста (UIA / буфер консоли), если сценарий его задаёт.
7. Копия проекта (без bin/obj/out) в папку сдачи; листинги отчёта заменяются содержимым файлов.

## Интерфейсы модулей (`forlabs/runner/`)

- `plan.py` — модели: `ProjectFile(path, content)`, `ListingRef(section, block, file)`,
  `ShotStep(action: set|select|click|check|type|key|wait|scroll|open, target, value)`,
  `ShotPlan(section, block, mode: window|console|browser|manual, steps, input, url, expect, reason)`,
  `ProjectPlan(language, kind, name, files, entry, listings, shots)`; `validate(plan) -> list[str]`.
- `languages.py` — `Toolchain(name, path, version)`, `detect() -> dict[str, Toolchain]`,
  `build(project_dir, plan, tools) -> BuildResult(ok, log, artifact)`, `run_spec(plan, artifact) -> RunSpec(cmd, cwd,
  console, env)`; шаблоны файлов сборки.
- `safety.py` — `scan(plan) -> list[str]` (пусто — можно запускать).
- `shots.py` — `Shooter` (протокол): `shoot(run: RunSpec, shot: ShotPlan) -> ShotResult(image_path | reason)`;
  `WindowsShooter` (winapi + uia + console + browser), `FakeShooter` для тестов.
- `winapi.py` — окна процесса, PrintWindow, задание с пониженным уровнем, метка Low на папку.
- `console.py` — ввод в окно консоли и чтение буфера (отдельный вспомогательный процесс: AttachConsole).
- `uia.py` — UI Automation через pythonnet (`System.Windows.Automation`).
- `computer.py` (этап 3) — цикл «снимок окна → действие модели → SendInput внутри окна», лимиты, Esc — стоп.
- `forlabs/pipeline/project.py` — этап конвейера: план → проверка → сборка/исправления → снимки → копия → листинги.

## Проверки

- Linux (здесь): план, проверка, опасное, сборка и запуск консольных программ C++/Python/Java/Node/PHP/Go без снимков,
  синхронизация листингов, конвейер с FakeLLM и FakeShooter; живой прогон модели на примерах лаб каждого языка.
- Windows (CI, задание «Программы лаб»): для каждого языка и вида — готовый план → сборка → запуск с пониженными
  правами → шаги → снимок не пустой и содержит ожидаемый текст (UIA/буфер консоли); MySQL — служба сборщика.
  Снимки уходят в ветку `probe-results`, их смотрит человек/агент.
- Сбои: нет инструмента, ошибка сборки после 3 кругов, программа зависла (таймаут), упала, окно не появилось,
  пустой снимок, опасный код, MessageBox поверх окна, программа ждёт ввода бесконечно — у каждого свой тест.

## Этапы

1. Проект + сборка + листинги + папка/zip (все языки), консольные снимки, WinForms, Edge, MySQL.
2. Swing/tkinter/WPF, PHP-сайт, проверка ожидаемого текста, установка недостающих инструментов по ссылке.
3. «ИИ управляет окном» для чужих программ.
