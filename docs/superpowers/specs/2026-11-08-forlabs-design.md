# ForLabs — дизайн приложения

Дата: 2026-11-08 · Статус: утверждено в диалоге, этап 1 в работе

## 1. Цель

Локальное Windows-приложение, которое по методичке выполняет лабораторную работу и выдаёт отчёт `.docx`, свёрстанный в точности как итоговые отчёты студента. Работает для нескольких людей (профили). ИИ — DeepSeek через OpenAI-совместимый API.

Критерии успеха:

1. Свёрстанный отчёт проходит сверку с каноном оформления (`docs/reference/formatting-canon.md`): 0 расхождений по каждому типу абзаца.
2. Отчёт проходит все проверки стандарта РС02-23 и анти-ИИ.
3. Предпросмотр в приложении показывает страницы, отрисованные самим Word (при наличии Word), включая рамки листингов, разрывы страниц, «Продолжение листинга N», номера страниц в содержании.
4. Теоретическая лаба (этап 1) проходит путь «методичка → готовый .docx» без ручной правки текста; вручную — только скриншоты, которые нельзя сделать автоматически.
5. Смена профиля (пол, ФИО, группа, варианты, руководители) меняет всё зависимое: вывод, титул, варианты, род глаголов.

## 2. Источники правил

| Что | Откуда (репозиторий `forlabsnotes`) |

| Оформление | снято программно с `Итоговые_отчеты/*.docx` (ССП, 1С, ПССИП, КС) → `docs/reference/formatting-canon.md`. Старые `make_*_docx.py` не эталон: оформление делалось вручную |
| 1С (этап 3) | `70_Resources/Procedure_1C_Lab_Execution.md`, `1c_absolute_perfection_rules.md`, `40_Decisions/*`, `.agents/skills/1c-*` |
| Анти-ИИ | «Антипалевный контур» из `User_Working_Profile.md`, `.agents/rules/stealth-anti-detection.md`, скилл `humanizer` |

Файлы других учащихся (папки с чужими фамилиями) не используются ни как образец, ни как данные.

## 3. Сценарий пользователя

1. Профиль: выбрать или создать (ФИО полностью, ФИО для титула «Д.Я. Лабынцев», пол, группа, специальность, колледж, город; записи по предметам: название на титуле, руководитель, учебный год, вариант, стиль меток шапки).
2. Новая лаба: предмет, номер, методичка (PDF, DOCX, изображения, вставленный текст).
3. Подтверждение разбора: тема, цель, оснащение, задания со сквозной нумерацией, вариант, контрольные вопросы, дата. Можно править.
4. «Выполнить»: этапы идут по очереди, страница отчёта заполняется на глазах.
5. Результат: предпросмотр как в Word, замечания проверок, слоты для ручных скриншотов (Ctrl+V), «переделать задание N».
6. Сдача: папка лабы с чистыми файлами и `.docx`; «Отчёт за семестр» собирает титул, содержание и все лабы предмета.

## 4. Архитектура: гибрид

```
Методичка → [1] Разбор → [2] План → [3] Выполнение → [4] Текст → [5] Проверка → [6] Вёрстка → [7] Word
             LLM+код      LLM         исполнители     LLM          код            код           Word/LO
```

Каркас фиксирован и гарантирует правила; гибкость (агентный цикл с инструментами) — только внутри шага 3, в рамках модуля предмета и с лимитами.

Что делает код, а не модель (жёсткие гарантии):

- шапка из разбора, дословные формулировки заданий и вопросов (проверка дословности);
- сквозная нумерация заданий (дополнительные — продолжение), рисунков, листингов, таблиц (нумерация с 1 в каждой лабе);
- подводка и подпись строятся из одной «темы» рисунка/листинга/таблицы: подпись = тема, подводка = тема + согласованное «представлен(а/о/ы) на рисунке N» / «в листинге N», «В таблице N представлены …»;
- вывод = цель с первым инфинитивом в прошедшем времени по полу профиля;
- вся вёрстка — по канону; финальная доводка — Word.

Состояния лабы: `draft → parsed → confirmed → executing → needs_manual → rendered → final`. Состояние сохраняется после каждого шага; после сбоя работа продолжается с последнего шага; задание можно переделать отдельно.

    antiai/     детекторы: текст (рус.), код, дизайн, сходство между профилями
    render/     шаблон, канон, сборка .docx (лаба и семестр), сверка с каноном,

`header_style=long`: «Тема работы:», «Цель работы:», [«Оснащение:»], «Задание:» (ССП, 1С). `short`: «Тема:», «Цель:», «Задание:», «Оснащение работы:» (ПССИП, КС).

### 5.2 Хранение

- Данные приложения: `%LOCALAPPDATA%\ForLabs\` (Linux для разработки: `~/.local/share/forlabs`), переопределяется `FORLABS_HOME`.
  - `settings.json` (адрес API, модель, пути к Word/LibreOffice/Tesseract);
  - `profiles/<id>.json`;
  - `labs/<profile>/<subject>/<lab>/state.json`, `assets/` (копия методички, оригиналы картинок, журнал);
  - `memory/<profile>/<subject>.md` — выжимка прошлых лаб для продолжения тем;
  - `rules/` — пользовательские правки правил поверх поставляемых.
- Ключ API: Windows Credential Manager через `keyring`; запасной вариант — переменная `FORLABS_API_KEY`. Никогда в файлах репозитория.
- Папка сдачи: `<output_root>/<предмет>/ЛР<N>/` — только `.docx` и файлы студента, без служебных.

### 5.3 LLM

- OpenAI-совместимый клиент; `base_url`, `model`, ключ — из настроек. Пресеты: «AI API Shop» (`https://api.aikeysforyou.com/v1`, модели `deepseek-v4.1-flash` / `deepseek-v4-flash`; другие модели ключ отклоняет с 403 `model_not_allowed`) и «DeepSeek напрямую» (`https://api.deepseek.com`). Проверено 2026-11-08: оба id моделей отвечают через первый адрес.
- Структурные ответы: JSON + валидация pydantic + до 3 попыток исправления с текстом ошибок.
- Агентный цикл (шаг 3, этапы 2–4): инструменты, лимиты (шаги, время, разрешённые команды по предмету), работа строго внутри папки лабы; не опирается на принудительный `tool_choice`.
- Изображения модели не передаются (поддержка не подтверждена): текст сканов — через OCR, если установлен Tesseract, иначе просим вставить текст.
- Промпт = роль + правила (по шагу и предмету) + LabSpec + факты профиля (пол, вариант) + память предмета.

### 5.4 Правила (`rules/`)

```

rules/common/voice.md          голос студента
rules/anti-ai/text.md          запреты и замены для текста
rules/anti-ai/code.md          стиль кода студента
rules/anti-ai/design.md        креативно, но без ИИ-штампов

```

Жёсткие правила продублированы в коде; файлы правил влияют только на то, что пишет модель.

## 6. Канон оформления и вёрстка

Полный канон — `docs/reference/formatting-canon.md`. Ключевое: A4, поля 30/15/20/20 мм; Times New Roman 14, одинарный интервал, по ширине, отступ первой строки 15 мм; код — Consolas 12 в общей рамке (pBdr single 0,5 pt); рисунки inline по центру, ширина до 16,5 см; подписи без точек.

- Шаблон: стили, тема, настройки, нумерация и параметры секции берутся из эталонного отчёта; тело очищается. Личные данные в шаблон не попадают — титул собирается из профиля.
- Документ лабы: «Лабораторная работа №N» (Heading 1) … «Вывод: …», без титула и содержания.
- Документ за семестр: титул (по эталону, «Выполнил/Выполнила уч-ся гр.<группа>», руководитель, год) → «Содержание» (поле TOC `\o "1-3" \h \z \u`) → лабы, каждая с новой страницы.
- Сверка с каноном: классификатор ролей абзацев + эффективное форматирование (docDefaults → стиль → прямое) сравниваются с каноном. Используется в тестах и как последний шлюз перед выдачей.

### 6.1 Доводка через Word (Windows)

1. Открыть `.docx` через COM (`pywin32`), обновить поля TOC.
2. Цикл продолжений: для каждого листинга найти страницы его строк; если строки листинга есть на странице p и p+1, перед первой строкой на p+1 вставить абзац «Продолжение листинга N» (без рамки, без отступа). Для таблиц — разделить таблицу по первой строке новой страницы, вставить «Продолжение таблицы N», повторить строку заголовка. Повторять, пока нет изменений (не более 10 итераций).
3. Снова обновить TOC, проставить свойства документа из профиля (автор, последний изменивший), сохранить, экспортировать PDF для предпросмотра.

Без Word: PDF через LibreOffice, продолжения не расставляются, документ помечается «нужна доводка в Word» (её можно запустить позже кнопкой). Пагинация LibreOffice отличается от Word на 1–2 строки — проверено на эталоне.

### 6.2 Предпросмотр (дизайн B)

Страницы PDF → PNG (PyMuPDF) → показываются в центре экрана. Во время письма предпросмотр обновляется после каждого задания; до шага 7 помечен «черновой вид».

## 7. Стандарт РС02-23 (проверки в коде)

Перенос и расширение `validate_lab_report.py`, но по структуре ReportDoc (а не по тексту):

- обязательные поля шапки, дата `ДД.ММ.ГГГГ`, запрет «Учащийся/Студент/Специальность/Вариант» в шапке;
- задания: сквозная нумерация, заголовок одной строкой, текст задания совпадает с методичкой;
- подводки и подписи: без точки на конце, подпись = тема из подводки;
- списки через дефис: со строчной буквы, `;` в промежуточных, `.` в последнем, внутри пунктов нет ссылок на рисунки/листинги;
- таблицы только если их требует задание или пользователь;
- контрольные вопросы только из методички, «N. Вопрос / Ответ: …», ответ до 22 слов и 165 символов;
- вывод = формула цели по полу профиля, одно предложение, без вводных слов;
- нет markdown, эмодзи, английских кавычек.

## 8. Морфология и пол

- Вывод: первый инфинитив цели → прошедшее время ед. ч. нужного рода (pymorphy3), остальное дословно, точка в конце: «Сформировать умения…» → «Сформировал/Сформировала умения…», «Научиться…» → «Научился/Научилась…». Если в цели есть другие инфинитивы через «и»/запятую — на экране подтверждения предлагается вариант с их заменой.
- Титул: «Выполнил/Выполнила уч-ся».
- Текст: модели сообщается пол; детектор проверяет согласование бессубъектных глаголов прошедшего времени единственного числа.

## 9. Анти-ИИ

Три уровня: правила (`rules/anti-ai/*`) → детекторы (код, выдают Finding с местом и причиной) → точечная переделка моделью только отмеченных мест (до 3 раундов), остаток показывается пользователю.

- Текст: запретная лексика пользователя («сгенерир-», «генерац-», «нейросеть», «ИИ», «модель» в значении ИИ, «chatgpt», «бот», «ассистент», «на оценку 9–10», «повышенного уровня сложности», «Пожалуйста»), ИИ-штампы («играет важную роль», «является ключевым», «в современном мире», «стоит отметить», «широкий спектр», «не только …, но и …», «В данной работе рассмотрены»), одинаковые начала абзацев, английские кавычки, markdown, эмодзи.
- Код: плотность комментариев, английские комментарии в BSL, `TODO`/`Fallback`, декоративные разделители и эмодзи в выводе, лишние try/catch, конструкции не по курсу.
- Дизайн: креатив поощряется; запрещены штампы (градиент `#667eea→#764ba2` и фиолетово-синие заливки, `backdrop-filter`, неоновые тени, эмодзи-иконки, Inter/Poppins по умолчанию, сетки одинаковых карточек, рекламные лозунги).
- Сходство между профилями одной лабы: шинглы текста и кода, порог настраивается.
- Файлы: в папке сдачи только файлы студента; метаданные `.docx` — из профиля.

## 10. Интерфейс

FastAPI + Jinja2 + немного JS (SSE для прогресса, вставка изображений из буфера), окно через `pywebview` или браузер. Экран лабы — вариант B «Документ»: слева этапы и «Нужно от тебя», в центре страница отчёта, справа замечания; вкладка «Журнал». Остальные экраны: Профили, Предметы, Лабы предмета, Новая лаба, Подтверждение разбора, Отчёт за семестр, Правила, Настройки (адрес API, модель, ключ, проверка подключения, найденные Word/LibreOffice). Все надписи — по-русски, прямо, без лозунгов.

## 11. Ошибки

- API: повторы с паузой; понятные сообщения про ключ, баланс, недоступность, неверную модель (403).
- Ответ модели не прошёл проверку: ошибки возвращаются модели, до 3 попыток; затем шаг «не пройдено» с причиной.
- Исполнитель: лимиты; невыполненное задание помечается, отчёт не финализируется молча.
- Нет Word / LibreOffice / Tesseract: работа продолжается с понятным предупреждением, что именно недоступно.
- Готовый отчёт не выдаётся как «готово», пока есть ошибки проверок, если пользователь явно не принял конкретное отступление.

## 12. Тестирование

- Морфология: пары «цель → вывод» из эталонных отчётов + женские формы.
- Проверки стандарта и анти-ИИ: чистые примеры проходят, испорченные — ловятся.
- Вёрстка: содержимое реальной лабы (без личных данных) → `.docx` → сверка с каноном, 0 расхождений; PDF через LibreOffice рендерится без ошибок.
- Разбор методички и конвейер: на записанных ответах модели (без сети); отдельный живой прогон с ключом.
- Windows-части (Word COM) — тесты пропускаются вне Windows, есть чек-лист ручной проверки.
- В тестах и репозитории нет реальных персональных данных: используется вымышленный профиль.

## 13. Этапы

1. **Ядро** (этот документ, реализация сейчас): всё из разделов 5–12 для теоретических лаб + слоты ручных скриншотов; интерфейс B.
2. Исполнители кода: C#, Java, Go, PHP/MySQL, HTML/CSS; настоящие скриншоты окон Windows; структура папок КПИЯП («Пример N», «Индивидуальное задание»).
3. 1С: XML в накопительную базу, загрузка Конфигуратором, заполнение и проведение документов, выгрузка `.dt`, батники, санитария журнала.
4. Сети: реальные команды, конфиги Packet Tracer, инструкции для ручной части.

Каждый этап 2–4 получает свою спецификацию и план.

## 14. Вне рамок

Облачный хостинг, мобильная версия, автоматическая отправка преподавателю, гарантия прохождения сторонних «ИИ-детекторов».

## 15. Риски

- Дословность разбора на «грязном» тексте PDF (переносы, колонтитулы) — нормализация + проверка + экран подтверждения.
- Хрупкость COM-автоматизации Word — изолированный процесс, тайм-ауты, повтор.
- Ложные срабатывания анти-ИИ — уровни строгости, ручное «принять».
- Сеть до API может быть закрыта — проверка подключения в настройках с понятной ошибкой.
