# «Своя программа»: отчёт по программе студента

Владелец: «да и добавь еще "своя программа"» — в ответ на вопрос студента «как твоей штуке скинуть прогу, чтобы она
по ней отчёт сделала». Владелец просил не тянуть («надо начать уже делать»), поэтому решения ниже — мои, с причинами.

## Зачем

Студент уже написал программу (сам, на паре, с одногруппником) и хочет только отчёт. Сейчас ForLabs всегда пишет
свою программу: листинги в отчёте — не его код, снимки — не его окна. Нужно: листинги — его код дословно, описание —
по тому, что его программа делает, снимки — запуском его программы.

## Что делает студент

- «Новая лаба»: под методичкой поле «Своя программа (если уже написал)» — ZIP или «Выбрать папку…» (системное окно
  выбора, как у папки сдачи; без окна — путь руками).
- Страница лабы: блок «Своя программа» — что взято (имя, сколько файлов, язык), «Заменить», «Убрать». Если отчёт уже
  написан — подсказка «Выполнить заново», чтобы отчёт перешёл на неё.
- Несколько методичек разных лаб в одной форме → программа не добавляется ни к одной (неясно, к какой), замечание.

## Как устроено

1. **Чтение** (`forlabs/ingest/own.py`): папка или ZIP → `<лаба>/own/` (копия через временную папку: сбой на
   середине не портит прежнюю; оригинал не трогается). Не обходятся папки сборки и служебные (`bin`, `obj`, `out`,
   `.vs`, `.git`, `.idea`, `node_modules`, `__pycache__`, `venv`, `packages`, `Debug`, `Release`, `target`, `dist`…);
   папки Unity (`Library`, `Temp`, `Logs`, `ProjectSettings`…) — только в корне Unity-проекта, в обычном проекте
   папка `library/` — это код. Корень: у проекта Visual Studio (один `.csproj`, весь код в его папке) — папка
   `.csproj`, имя проекта — его `RootNamespace` или имя файла (иначе ресурсы `Properties.Resources` получат чужое
   имя и программа упадёт при запуске); иначе снимается общая верхняя папка. Код — по расширениям языков ForLabs
   плюс данные; остальное ≤ 20 МБ файл, ≤ 200 МБ всего — ресурсы. Язык — по большинству файлов кода; сайт — только
   если другого кода нет (Flask с шаблонами — Python). Unity — по `Assets/` + `ProjectSettings/` или `.meta`.
   Неподдерживаемый архив (пароль, Deflate64) — понятная ошибка, а не сбой создания лабы.
2. **Состояние**: `LabState.own: OwnProgram | None` — имя, язык, движок, список файлов кода, ресурсы и `text` — код для
   модели (до 60 000 знаков: главные файлы первыми, остальное перечислено по имени). `text` хранится в состоянии, чтобы
   отчёт писался и на другом компьютере; сами файлы (`own/`) — локально, как оригиналы методички.
3. **Текст отчёта**: `_memory_text` первым блоком отдаёт программу студента с правилом: листинги — только её код,
   дословно; описание и выводы — по тому, что она делает; своей программы не придумывать.
4. **Проект**: если язык поддерживается и движка нет — `needs_project` истинно и без листингов. `plan_project` получает
   программу студента и правило «files — ровно эти пути с пустым content, ForLabs подставит текст сам». После ответа
   модели язык и имя проекта — студента, `with_own` ставит его код дословно (лишние файлы модели убираются,
   пропущенные добавляются). Ресурсы и данные идут в план, пока он укладывается в пределы проверки; файлы другого
   вида (шаблоны `.html` у Flask, `.sql` у C#) и не влезшее кладутся в папку программы как есть. Из старых проектов
   .NET Framework не берутся `Properties/AssemblyInfo.cs` и неиспользуемый `Properties/Settings.Designer.cs`.
   Отпечаток программы хранится в проекте: другая программа (добавили, заменили, убрали) — проект составляется
   заново, без прежнего плана («Повторить» и чат не соберут старую).
5. **Исправления**: сборки — разрешены, как для любого проекта (программа могла собираться под другую версию
   среды); после сборки студент видит, какие файлы ForLabs поправил. Просьба из чата исправить программу, когда
   план составляется заново, применяется поверх файлов студента (а не теряется за ними).
6. **Unity и прочие движки**: код идёт в листинги, проект не собирается — как сейчас для Unity.

## Не делаем сейчас

Чат «сделай по моей программе», синхронизация `own/` в облако, программа из нескольких решений `.sln` с разными
языками.

## Подходы

- **A (выбран)**: программа студента — фиксированные файлы плана; модель планирует только листинги и снимки. Весь
  остальной путь (сборка, снимки, папка сдачи, исправления) — общий с обычным проектом.
- B: программа студента как «материал» (как ZIP преподавателя). Дёшево, но модель перепишет код по-своему — студент
  получит не свою программу.
- C: отдельный путь «только снимки, без плана». Пришлось бы заново делать запуск, сценарии и папку сдачи.
