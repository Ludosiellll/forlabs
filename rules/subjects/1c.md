# 1С:Предприятие

## Дисциплина
Платформа «1С:Предприятие 8.3» (учебная версия): режимы «Конфигуратор» и «1С:Предприятие», объекты метаданных (подсистемы, справочники, документы, нумераторы, перечисления, константы, функциональные опции, регистры сведений и накопления, отчёты на СКД, обработки), формы, модули, встроенный язык.

## Накопительная база
- Все лабы ведутся в одной сквозной базе: каждая следующая достраивает предыдущую. Объекты и данные прошлых лаб приходят в блоке «Память предмета».
- Даже если методичка пишет «будет добавлена новая информационная база», объекты добавляются в эту же базу по подсистемам. Не пиши «создал новую базу».
- На объекты прошлых лаб ссылайся как на существующие: «в созданный ранее справочник «Номенклатура» добавлен реквизит …».
- Все документы в базе проведены (зелёные отметки), черновиков нет.
- Ввод на основании — только тот, что есть в методичке; приходная накладная основанием для расходных документов не служит.
- В табличных частях нет пустых расчётных колонок и ссылок на группы справочников.

## Что писать в задании
- Называй объекты и реквизиты как в конфигурации: документ «Продажа», табличная часть «СписокТоваров», регистр накопления «Продажи».
- Реквизиты и свойства — списком по образцу: «- склад (тип данных «СправочникСсылка.Склады»);», последний пункт с точкой.
- Путь выгрузки .dt и имя файла бери из запроса, сам не придумывай.

## Рисунки — снимает студент вручную
Для каждого рисунка дай инструкцию: режим → раздел или ветка дерева → что раскрыть → какой объект, документ или карточку открыть → какая вкладка → что должно быть в кадре.
- «Конфигуратор: дерево конфигурации → раскрой «Документы» → открой «Продажа» → вкладка «Данные»; в кадре реквизиты шапки и табличная часть»;
- «1С:Предприятие: раздел «Документы» → «Продажа»; в кадре список документов с отметками проведения»;
- «1С:Предприятие: раздел «Отчёты» → «Продажи» → «Сформировать»; в кадре таблица с итогом».
Обычные рисунки: дерево конфигурации с новыми объектами; окно редактирования объекта; форма элемента или документа с заполненной табличной частью; список проведённых документов; движения документа по регистру; сформированный отчёт; форма обработки с результатом; окно диалога ввода.

## Код BSL
- комментарии короткие и только по-русски: «// пересчет суммы»; без TODO, Fallback и других английских слов, без блоков «// Параметры: …»;
- диалоги синхронные: ВвестиЧисло, ВвестиСтроку, Предупреждение (модальность в конфигурации включена); без ОписаниеОповещения и асинхронных «Показать…»;
- запросы как из конструктора: ВЫБРАТЬ, ИЗ, ГДЕ, СГРУППИРОВАТЬ ПО, УПОРЯДОЧИТЬ ПО, КАК — капсом, строки продолжения начинаются с «|»;
- в ОбработкаПроведения — Движения.<Регистр>.Записывать = Истина;
- пересчёт в табличной части — обработчик ПриИзменении на клиенте: Сумма = Количество * Цена; расчёты через Окр(…, 2);
- поиск документа по номеру — НайтиПоНомеру, как в методичке, без перебора на случай неудачи;
- после программного изменения документа — короткое Сообщить(…) и ОповеститьОбИзменении(Ссылка); без «успешно создан и проведен»;
- нет пустых #Область, пустых процедур, пустых Попытка…Исключение; диалоги ввода не заменяются константами.

## Надписи интерфейса
- кнопки и группы без пояснений в скобках: «Создать элемент», а не «Создать элемент (пользовательский ввод)»;
- естественный порядок слов: «Новый склад», а не «Склад новый»;
- предупреждения без «Пожалуйста»: «Выберите документ!», «Не выбран документ!»;
- форма документа — один экран: шапка сверху, табличная часть ниже, без лишних закладок;
- поля ввода на форме обработки — выше кнопки действия.
